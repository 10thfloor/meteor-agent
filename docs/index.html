Why it exists
Durability

Crashes don't lose work

Lease and heartbeat, atomic seq allocation, repair-on-entry. If the server dies mid-sentence, the next one picks up where it left off.

Channels

One agent, five surfaces

Slack, email, SMS, WhatsApp, Telegram. Each verifies webhooks, ingests media, and threads replies. The agent definition never changes.

Participants

n humans × n models

Multiple people and multiple models in one session, with per-message attribution, @-mention addressing, and durable model-to-model relays.

Memory

Recall the user can read

Durable facts about the person and about the work, in a collection your UI can show, edit, and delete. Semantic search, no second database.

Up and running

Five steps from an empty file to two agents collaborating in a Slack thread. Every block below is real API, not pseudocode.

1 Define the agent

A name, a model, instructions, and tools. The registry entry lives on the server; the name is shared with the client.

server/agents.ts
import { Agent } from 'meteor/10thfloor:agent';

const Support = new Agent('support');

Support.define({
  model: 'anthropic/claude-sonnet-5',
  instructions: 'You help with customer orders.',
  tools: ['orders.lookup'],
  budget: { turns: 20, toolCalls: 40 },
});

2 Give it a tool

Co-registration defines the Meteor method and the tool at once — your UI and the model call the same code through the same schema.

server/orders.ts
export const lookup = Agent.method('orders.lookup', {
  description: 'Look up an order by id',
  args: {
    type: 'object',
    properties: { id: { type: 'string' } },
    required: ['id'],
  },
  run(args) {
    // `this` is the method invocation, so
    // this.userId scopes the query to the caller
    return Orders.findOneAsync({
      _id: args.id,
      userId: this.userId,
    });
  },
});

Support.define({ ..., tools: [lookup] });  // the model
await Meteor.callAsync('orders.lookup', { id });  // your UI

4 Connect a channel

The same agent, now reachable on Slack. The channel package handles signature verification, parsing, and delivery.

server/channels.ts
import { slack } from
  'meteor/10thfloor:agent-channel-slack';

Agent.channel('slack', slack({
  agent: 'support',
  botToken: process.env.SLACK_BOT_TOKEN,
  signingSecret: process.env.SLACK_SIGNING_SECRET,
  admits: 'linked',
}));

Register a second agent and add it to the session roster. Now users can @-mention either one in the same thread.

What's in the box

Everything needed to run production agents inside a Meteor app — no external orchestrator, no second database, no separate deploy.

Tools

Five kinds: Meteor methods, inline functions, co-registered pairs, subagents, and MCP servers. Model arguments are checked against the full JSON Schema.

Approval gates

gate: 'ask' parks the turn for a human. Budgets cap turns, tool calls, and spend; unanswered approvals time out and auto-deny.

Streaming

Token deltas through a capped collection — O(chunk) on the wire, not O(n²). Merged client-side into one ordered cursor.

Compaction

Past the context threshold, older turns are summarized. The model's view shrinks; the transcript keeps every row and your UI keeps rendering it.

Channels

Slack, email, SMS, WhatsApp, Telegram. Media ingest runs through host allowlists, size gates, and redirect-safe fetching.

Participants

Rosters up to 16. Membership is the authorization; attribution is stamped by the harness, never by a model.

Memory

Durable recall in a Mongo collection. Semantic search through mongot, degrading to text and regex rather than failing a turn.

Subagents

Another agent behind a tool call, with composed budgets, a depth guard, and its own child transcript.

Forking

Branch a conversation at a batch-safe point. The fork copies transcript and roster; the source continues untouched.

Recovery

A watcher sweeps for sessions holding dead leases after a deploy, an OOM, or a SIGKILL, and re-runs the turn.

Group sessions

A session holds up to 16 participants in any mix of humans and models. The roster is the authorization: on it, you can read and write; off it, ingress settles the event silently.

  • Per-message from attribution, stamped by the harness from the authenticated source — a model can never claim to be someone else
  • @analyst routes the turn to that model, running its config against the primary's budget
  • A model reply starting with @colleague schedules a durable relay, written atomically with the commit
  • The relay counter resets on every human message, so agents cannot loop forever
  • Each model sees colleagues' spoken conclusions, not their tool calls
  • Compaction uses an omniscient view, so summaries preserve every speaker
the participants API
// Add a model to the conversation
await Agent.participants.add(sessionId, {
  id: 'm:analyst',
  kind: 'model',
  role: 'member',
  agent: 'analyst',
}, { by: 'm:support' });

// Add a human by channel identity
await Agent.participants.add(sessionId, {
  id: 'x:slack:U024BE7LH',
  kind: 'human',
  role: 'member',
  identity: {
    kind: 'slack',
    externalUserId: 'U024BE7LH',
  },
  displayName: 'Dana',
});

// Read the roster, or remove someone
// (the owner can't be removed)
const roster = await
  Agent.participants.list(sessionId);
await Agent.participants.remove(
  sessionId, 'm:analyst');

Memory

An agent that only knows this conversation forgets the person the moment it ends. memory: true gives it durable recall — about the people it serves, and about the work itself — as a Mongo collection your UI can read.

  • Memory follows the human, not the model. The store is keyed by userId alone, and a turn always runs as the session owner — so what support learns, analyst recalls
  • Work memory (scope: 'app') carries no userId at all: one pool, read by every agent in every session
  • Promoting a fact there is an approval — and so is deleting one
  • Nothing enters context invisibly: every recall is a memory_search tool row in the transcript
  • Search degrades rather than failing a turn — vector, then text, then regex
  • Your UI subscribes to the same collection, so the user holds the delete button
server/agents.ts
Support.define({
  model: 'anthropic/claude-sonnet-5',
  instructions: 'You help with customer orders.',
  memory: { scopes: ['user', 'app'] },
});

// The user's memory page — same collection, same rules
Meteor.subscribe('agent.memories');
await Meteor.callAsync('agent.memoryForget', { id });
