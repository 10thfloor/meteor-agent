# Evidence and source-linked observations

The core records a private trace for every leased agent turn. Model spans contain
request digests, duration, token counts, and reported cost. Tool spans contain a
result-specific human summary when the tool provides one, plus a private,
bounded and credential-redacted audit copy. Provider requests, system prompts,
and reasoning text are not copied into trace storage.

`listSessionEvidence(sessionId, { includeDebug: false })` returns `traces`,
`spans`, `manifests`, and `feedback`. Only explicit `includeDebug: true` adds the
private tool audit view. The host must authorize the session before invoking
this server API; it registers no public Meteor method. Constellation additionally
requires the Mission's debug setting before returning this view.

The turn manifest identifies the model, prepared tool catalog (including MCP
server and approval gate), available Skills, frozen Memory Frame, constitution,
practice revisions, facts, experiences, and source message digests. A manifest
proves availability, not that the model consulted every listed memory. Model
spans identify the exact effective request through a digest after hooks and
protected memory finalization.

Use `recordEvidenceFeedback({ traceId, actorId, rating, note })` to attach one
editable `helpful` or `unhelpful` verdict per reviewer to a trace. Feedback,
traces, private tool audits, manifests, and observations follow session erasure.
Admitted Experiences retain the existing Agent/owner/session audience lifecycle.

## Tool projections

An inline or adopted Meteor tool can return:

```ts
return toolOutput({
  model: { count: 3, references: compactReferences },
  display: 'Found 3 references',
  transcript: 'Three references were checked.',
  raw: fullLookupResult,
});
```

The model receives only `model`; normal UI receives `displayContent` and
`transcriptContent`; `raw` stays in the private audit store. Existing tools retain
their current model result and generic human activity label. The helper uses a
local symbol so JSON from an MCP server cannot forge a host-defined projection.
The `afterToolResult` hook may supply the same `display`/`transcript` fields and
replace the model `value`. Raw audit storage is bounded and credential-redacted
even when debugging is enabled.

## Observations and reflection

At each committed final reply, identity-enabled agents capture an observation
with exact source message IDs, sequence numbers, and content digests. Initial
observations are labeled excerpts; they do not claim a lesson was learned.
`readObservationSources(id)` verifies all sources before returning the originals.
Changed or deleted source material cannot silently support a new Experience.

Hosts can register a summarizer through `setObservationResolver(resolver)`. Its
input includes `agentId`, `sessionId`, exact source `messages`, `priorSummary`, an
abort `signal`, and a dedicated background `traceId`. It returns `{ summary,
experience? }`. A candidate Experience contains `expectationBasis`, `expected`,
`observed`, `difference`, `lesson`, `context`, and `confidence`. It should be
omitted when no meaningful expectation/outcome difference is supported.

Automatic reflection is off until a host explicitly registers
`setObservationPolicy(async ({ agentId, sessionId }) => boolean)`. The completed
answer is available immediately while enabled reflection runs under its own
session lifecycle guard. The observation exposes `processing` and a safe `error`
for loading/retry UI. A bounded processing claim prevents overlapping reflection
writes, and a background trace does not replace the foreground turn's trace.

`reflectObservation(id, { draft? })` is the explicit reflection/edit operation.
The draft can be supplied by a human or generated by the configured resolver.
The frozen Memory Frame determines admission:

- Reviewed policy saves a `candidate`. `admitObservationExperience(id,
  { actorId })` records it after explicit review.
- Automatic policy records a candidate immediately as an automatic Experience,
  with provenance and the existing pending-audit/backlog rules.
- `dismissObservation(id, actorId)` dismisses unadmitted observations.

Admission claims the immutable winning candidate before recording it. A retry
reuses the same deterministic Experience source; edits and dismissal cannot
change a candidate while admission is in progress. The `admitting` state is
repairable by invoking the same admission API again after a failed write.
Reflection never changes Constitution or activates/hardens Practices directly.

## Delegation policies

Developer-defined Crew edges can pin `version` against `AgentConfig.version`,
set a `budget` with `toolCalls`, `spend`, and `maxIterations`, transform the
explicit delegated prompt through `context`, and apply `beforeDelegate` and
`afterDelegate` hooks. The before hook returns `true`, `false`, or a tighter
`{ prompt, budget }`. The completion hook receives only the final text and
success/error outcome, and returns `{ model, display?, transcript? }` or `false`.
Exceptions and malformed hook outputs fail closed with safe errors.

Child sessions persist the original request digest, exact version pin, and
effective budget ceilings. Recovery reuses an existing child before running
prompt hooks again, preventing nondeterministic hooks from creating duplicate
work. The current definition may tighten a child's limits after birth; it cannot
enlarge the stored ceilings. A changed pinned version stops resumed work and is
rechecked before tool side effects. Existing cancellation and child approval
surfaces remain in the shared session lifecycle.

No parent transcript is automatically forwarded to a delegated agent, and no
child tool-result payload is returned to the parent model. A context callback
receives only the explicit delegation prompt and trusted routing context. Its
caller may use application-owned data to produce an intentionally scoped prompt.

Package startup calls `ensureEvidenceIndexes()` and `ensureObservationIndexes()`.
The private collections deny all direct client mutations, including when a host
accidentally uses Meteor's `insecure` package.
